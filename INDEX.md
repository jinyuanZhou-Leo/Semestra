Semestra is a full-stack scheduling and academic planner with a Python backend and modern web frontend.
The repository root now exposes convenience npm entrypoints for starting the frontend and backend, while frontend package management still lives under `frontend/`.
`backend/` provides FastAPI APIs, data models, persistence, schema-level widget layout validation, env-backed JWT signing plus HttpOnly auth-cookie session transport with CSRF-protected browser writes and logout-driven session-version revocation, Program-level subject-code color-map persistence with stable assignment locking for existing codes plus collision-aware picks for newly discovered codes, account-wide course-resource file storage with local-disk persistence, bounded upload reads, saved external URL resources, and a 50MB quota, alongside an Alembic-managed schema migration path instead of runtime DDL rewrite helpers. The backend now also persists database-backed login-throttle buckets, Resend-backed email verification challenges plus one-time verification tokens for register/login/reset flows, an irreversible current-user deletion path that clears owned academic data plus stored course-resource files, and an app-level Host allowlist, while the LMS layer supports multiple encrypted provider-neutral integrations per user, Program-level integration selection, Course-to-LMS linking through dedicated metadata rows, LMS course import into Programs or Semesters, and read-only Navigation, Announcement, Module-summary, Module-item, Assignment, Grade, Page, Quiz, Syllabus, File metadata/download, and Calendar aggregation APIs with Canvas as the first adapter, with provider-specific config normalization, outbound SSRF hardening, credential masking, normalized module-item target metadata, inline module-summary item hydration for the main Canvas modules response, and safe file proxy/download handling inside the provider adapter layer instead of shared schemas/services. Course CRUD now also validates semester reassignment against the owning Program and correctly recomputes stats for Program-level courses even when `semester_id` becomes null. Account backup import/export is now split so `main.py` keeps thin route wrappers while a dedicated backend transfer module owns the full restore/export pipeline for LMS/resources/schedule/todo data, and the API layer is further modularized across focused auth, schedule, layout, shared-helper, CRUD-slice, and runtime-projection modules so no single backend entry file exceeds 1k lines while `backend/crud.py` stays a thin facade over focused `crud_*` modules. The backend startup path now also checks for required head-schema tables and columns up front, so drifted SQLite databases fail with a migration instruction instead of surfacing late endpoint-level 500s, and the production deploy script now loads the same systemd env file before migrations so schema upgrades target the live database and legacy SQLite deployments receive explicit backfill revisions for missing `programs.subject_color_map`, `courses.color`, `course_resource_files`, LMS schema changes, drifted `semesters.review_ready` columns, the newer Program/Semester plugin `is_enabled` flags that distinguish disable from delete, the auth email-verification tables and `users.email_verified_at`, and the V2 `tab_settings` plus `workspace_tab_order_entries` tables. Public plugin identity plus `tabs`/`widgets`/`settings` metadata now come from generated backend manifests under `backend/generated/plugin-manifests/*.plugin.json` plus optional `*.setup.schema.json`, emitted from typed frontend `frontend/src/plugins/*/plugin.ts` authoring entries, while private builtin/host-shell kind and visibility rules come from `frontend/src/plugins/host-policy.json`; Plugin System V2 now treats `builtin-dashboard` and `builtin-setting` as host-shell tabs instead of public plugins, persists tab-type-owned settings separately from widget-instance settings, backfills legacy Program installation settings into Program-scoped tab rows during migration, preserves assigned-course tab overrides as course-scoped rows, auto-reconciles duplicate or divergent assigned-course legacy tab rows into a deterministic shared semester course-tab order so dirty local SQLite databases can still migrate forward, rejects runtime-tab settings writes before persisting when the addressed tab/widget entry is missing, returns tab/widget-level availability for runtime tabs and widgets, keeps host-managed ordering in dedicated workspace buckets, and now assembles those runtime projections through a dedicated backend helper instead of inside the FastAPI entrypoint. The frontend now also includes a Canvas-only course navigation plugin that mirrors the Canvas web app with a sticky course-menu rail, a Home view defined by Canvas `default_view`, first-class Assignments and Grades views with a standalone restrained Gradebook handoff card, native Announcements/Modules/Pages/Quizzes/Syllabus views, a shrink-safe detail shell that prevents intermediate-width horizontal overflow, and still-open module sections whose item rows now arrive inline with the main modules payload instead of triggering one follow-up request per expanded section. The Grades tab now reads real Canvas grade data through a dedicated backend `/courses/{course_id}/lms/grades` chain backed by the Canvas Enrollments API instead of reusing local Gradebook data, while the rest of the Canvas browser keeps shadcn alert treatment for locked pages, host-aligned unavailable empty-state sizing, CTA-only handling for unknown internal tabs plus external tools, same-course page links kept inside Semestra, Canvas-specific page-link metadata preserved in sanitized HTML, richer Canvas table/image support with preserved inline styles, a tuned typography layer for Canvas rich-text bodies, a host-aware sticky rail offset that clears the Course Homepage title bar, LMS-origin resolution for relative Canvas links, a plugin-local navigation UI state that survives remounts, and a longer-lived client cache so revisiting pages does not hit the API every time. The frontend plugin layer now also exposes a formal workspace-local tab-jump host API so plugins can switch to existing tabs by id or tab type with host-managed confirmation, active semester/course tab runtime scope for instance-local UI-state keys, a plugin-local UI-state cache for transient widget/tab UI state that survives remounts without backend persistence, a manifest-backed `plugin-sdk` authoring surface, setup authoring centered on `setup.tsx` as the single source of truth for both frontend wizard rendering and backend schema generation, and host-reserved Dashboard/Settings shell tabs that stay outside the public plugin catalog while Semester/Course pages render tab/widget-level unavailable states directly from runtime availability payloads, including Gradebook Plan Mode and What If UI state. The auth routes now keep client-side validation feedback at the field level by driving shadcn invalid states directly on the affected login/register/reset inputs, validate email format on the client, use shadcn `InputOTP` for email-code entry, show non-layout-shifting inline hints, persist the registration nickname through the backend user `nickname` field instead of keeping it as unused local form state, and suggest common email domains once users type `@` while suppressing conflicting browser autofill UI so login, registration, and password-reset email fields share the same faster address entry behavior.
Canvas module item drill-down now keeps supported non-external/non-discussion items in-app, shows File items through locally cached native blob-backed previews, and leaves only External and Discussion items opening Canvas.
The frontend also layers business-level semantic empty-state wrappers on top of shadcn primitives so create, no-results, not-found, and unavailable states share one design language without modifying `components/ui/`, and standardizes ordinary settings forms around shadcn `Field` patterns with descriptions/errors grouped consistently and switch controls aligned to the right. The settings workspace now exposes reusable LMS integration cards, with Canvas still the only LMS UI while provider-specific payload mapping lives in a settings-local provider-definition layer instead of the generic manager component. Program settings now live on a dedicated breadcrumb-aware route with separate LMS and general sections, and now also own Program-level plugin management for installation, pinned version, Program defaults, and plugin-owned settings sections rendered with host-provided scope ids. Program-level plugin changes now invalidate downstream Semester, Course, and plugin-system caches so disabling a Program plugin immediately removes it from dependent workspaces on the next read, while runtime Semester/Course homepages now also hide already-persisted plugin tabs and widgets whenever that owning Program plugin is disabled, Program and Semester management tables now expose header-level bulk switches backed by transactional bulk mutation APIs instead of per-row request fan-out, Semester `locked` plugins are now enforced server-side across single-disable, bulk-disable, and delete mutation paths, Program-level plugin deletion also clears the plugin's persisted Program-scoped runtime data instead of only deleting the installation row, and unassigned Courses now gain their own lightweight plugin enablement layer that only surfaces Program-installed plugins with eligible course surfaces. Semester creation has moved out of the dashboard dialog into a standalone draft-first wizard with Basics/Courses/Plugins/per-plugin Setup/Review steps, debounced Basics plus plugin-setup autosave, the same shadcn date-range plus Reading Week fields used by Semester settings, refetch-safe local draft hydration that no longer overwrites newer unsaved basics/plugin-setup edits, parallel plugin-setup saves, setup-step visibility derived from the union of enabled Semester activations and plugin-system setup payloads so stale activation payloads cannot hide real setup work, plugin-level Next-step validation, default host-rendered setup components with optional plugin-owned setup/review overrides, host-aligned setup shells and field ordering, no duplicate in-content plugin titles during setup steps, a concise single-panel review summary with prose recaps for courses and plugins, explicit draft discard, setup-aware step normalization when enabled plugins no longer contribute setup fields, finalize-safe teardown of draft-only setup queries before routing into the activated Semester, server-backed review blockers plus plugin setup summaries before finalize, a transactional bulk plugin-activation path for the wizard's all-on/all-off control so the client no longer fans out one request per plugin, and conflict-safe draft creation that resumes an existing server draft instead of surfacing `SEMESTER_DRAFT_EXISTS` to the UI, while Program Dashboard only keeps a lightweight entry that can resume or discard an in-progress draft. Semester settings now also expose a dedicated post-create plugin management panel for enablement, Program-vs-Semester value comparison, and explicit override saves, while keeping every Program-enabled plugin visible there even before Semester import as an off-state row, hiding Program-disabled plugins entirely, rendering shared plugin settings headers with manifest icons, and limiting Semester management actions to enable/disable so data-destructive deletion cannot happen from that settings surface. Program, Semester, and Course entity contexts now keep detail records fresh for longer so workspace re-entry can reuse cached names and settings state, while Semester and Course breadcrumbs now resolve parent Program/Semester labels from that shared query cache instead of issuing ad hoc mount-time fetches. Course workspaces now also render a single-line `Semester / Course` title in the sticky header, let the course-name trigger switch to sibling courses from the same semester via a shadcn dropdown menu backed by the shared semester detail cache, expose a compact `cmd/ctrl + ↑↓` `kbd` hint, throttle repeated sibling-course switching to absorb held shortcuts, animate incoming course names with a non-linear spring by direction, and shake the title treatment when users try to move past the first or last course. Program Dashboard now surfaces that settings navigation as a right-aligned shadcn-style action, includes unassigned Program-level courses in its All Courses list and credit summary, adds a pencil-triggered course edit mode with per-row destructive deletion confirmed through shadcn `AlertDialog`, and GPA Percentage display is now normalized through a shared host-agnostic formatter so pages, dialogs, backup preview, and plugins all keep one decimal place without coupling plugin code to route-level implementations. Course settings manage link/sync/unlink actions, Add Course can parse ICS files into Program or Semester courses and asks for confirmation before manually creating a duplicate course name, shared settings CRUD panels keep horizontal scrolling contained inside their cards with shrink-safe section columns, stacked mobile headers, and tighter mobile minimum widths for wider tables, the unassigned-Course plugin panel intentionally exposes only enable/disable plus plugin info actions, and the Course Resources plugin keeps its add-resource dialog height stable across upload/link tabs while deleting saved-link resources without tripping backend storage-root unlink errors.
