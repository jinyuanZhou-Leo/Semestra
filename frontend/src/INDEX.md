Application source root containing entrypoints, routing shell, and domain modules.
Feature behavior is composed from components, contexts, hooks, services, the app-side `data/` layer, and utilities with TanStack Query-backed server-state caching, context-safe optimistic synchronization, and business-layer semantic empty-state wrappers.
Auth boot now relies on credentialed cookie sessions instead of browser-stored bearer tokens, with central session refresh and sign-out handling, Resend-backed email verification codes for register/login/reset flows, non-enumerating auth submit responses, and an email-driven `continue` path that decides login versus registration only after mailbox proof before the client proceeds. The frontend now exposes that through a unified `/login` public auth entry with Google, email, and password branches, while `/register` only survives as a compatibility redirect so the product no longer presents two competing auth homepages. It also keeps an explicit client-side session-clearing path for irreversible account deletion, and 401 interception that ignores auth-submit endpoints.
The standalone `calendar-core/` domain layer now sits beside `plugins/` so Calendar event contributions can register through a dedicated API rather than the plugin loader.
The plugin-system now keeps host-coupled built-in behavior out of the public plugin contract by using typed frontend `plugin.ts` authoring entries plus private `host-policy.json` overlays, generating backend-readable `backend/generated/plugin-manifests/*.plugin.json` and optional `*.setup.schema.json` files from those entries, exposing a single frontend `plugin-sdk` authoring surface, and exposing runtime instance scope helpers plus a frontend-only plugin UI-state cache for transient UI state without touching backend persistence. Plugin setup authoring is now centered on `setup.tsx` as the single source of truth: the frontend setup contract serializes those definitions back into backend schema, removes host-side `persist` semantics, and custom setup/review components receive draft `semesterId/programId` context so plugins can use normal APIs directly during setup while the host only stores raw `setup_values`. Settings sections now receive a stable `pluginId + scope + onRefresh` contract instead of framework-managed shared-settings props, runtime tab/widget definition and prop types now also export from the same public `@/plugin-system` surface instead of service-registry internals, the plugin facade is split across thinner host/public-type/settings-section surfaces with dedicated internal catalog/load-state/runtime-loader helpers behind `index.ts`, semester/course settings pages resolve missing tab-plugin settings to terminal unavailable states instead of endless loading placeholders, runtime homepage/plugin availability now comes from a single API-normalized `runtime` payload whose tab/plugin wire-shape cleanup happens inside the API layer instead of in hooks or runtime availability helpers, and unassigned Course settings now add a lightweight plugin enablement surface driven by backend-filtered course-eligible plugin tabs/widgets.
The plugin-system now also exposes a workspace-local tab-jump host API so plugins can request confirmed in-workspace navigation by tab id or tab type without inventing their own `window`-event hacks, and a plugin UI-state hook backed by localStorage plus memory fallback for transient widget/tab UI state. Course and semester pages now provide the same runtime instance scope to active tab renders that widgets already had, so tab plugins can use the UI-state cache cleanly.
Authenticated workspace chrome now also exposes a slash-triggered global command palette built from shadcn `Command` + `Dialog`, combining lazy account-wide Program/Semester/Course navigation, direct root/settings jumps, theme/privacy actions, active-Program workspace switching, and page-injected workspace operations such as tab switching or widget/course creation. The global navbar now also owns active-Program selection through a shadcn dropdown workspace switcher so Program-level pages can keep shorter breadcrumbs while the auth layer continues to normalize and mutate the required active Program id that lets `/` enter the current Program Home when Programs exist.
Plugin-global settings sections are now a host-rendered registration surface with shared scope ids and simpler shadcn card headers, while builtin or domain-specific plugins can persist through Program tab settings when they need higher-level defaults outside Program plugin-governance rows, as shown by Program-level Todo and Gradebook defaults that now seed downstream workspaces without reviving the removed plugin-settings table path.
Authenticated sessions can now optionally preload still-idle plugins in the background after the page load event by using browser idle time, with the toggle stored in global user settings.
The settings workspace now also treats LMS integrations as server state by loading saved integration records through TanStack Query, validating drafts before save, and reusing a generic in-place status button for validate/save actions. Canvas remains the only LMS UI, but provider-specific config/credential mapping now lives in a settings-local provider-definition layer instead of `LmsIntegrationManager` itself. Program and Course surfaces then consume those integrations for Program-level LMS selection, Course link/relink/unlink, and LMS import flows, with Add Course now sharing the same height-stable LMS picker patterns plus wizard-specific close-after-success behavior, Program Dashboard entering the new Semester wizard through a lightweight resume/discard-aware action, Program and Semester plugin management tables both exposing header-level bulk enable switches backed by transactional bulk APIs, Course workspaces now sourcing visible plugin/runtime settings state only from the Course inheritance payload while unassigned Courses expose a dedicated enable-only plugin management panel, Semester settings exposing a dedicated post-create plugin management panel for enablement and override maintenance, all Program-enabled Semester plugins staying visible there even before Semester import as off-state rows, plugin-owned settings sections carrying manifest-icon plugin headers, and shared settings data tables now leaving minimum-width policy to each concrete table while keeping horizontal scrolling contained inside cards with shrink-safe content columns, narrower four-column and two-column settings tables where appropriate, configurable empty-row heights, scroll-contained full-height wizard tables, no shared-shell scrollbar-gutter reservation, menu-based row actions, and a destructive account zone that requires typed confirmation plus a second destructive confirmation before calling the backend hard-delete endpoint and clearing local auth state.
